# Compact LVGL UI

M5StickC Plus2向け**135×240の縦画面**。C++の`CompactUi`はLVGL 7とArduinoJson 7に依存し、
ブラウザ・通信・GPIO処理を持ちません。実機にはLVGLの表示ドライバと物理ボタンのedgeを接続します。
日本語フォントは`../touch-ui/vibe_jp_16.c`を共有します（同ディレクトリのOFL.txt参照）。

現在の実機ラッパーは[GarVibeRemote-M5StickC](https://github.com/ThousandsOfTies/GarVibeRemote-M5StickC/blob/main/firmware/stickc-plus2/README.md)の
`firmware/stickc-plus2/`です。同ProductのWebシミュレータも、このUIをWASMとして使用します。
実機との接続はProductのUSB／SPP中継で行います。

## 表示と操作

本文は9px/秒で縦スクロールします。先頭で1.8秒、末尾で2.8秒停止してループします。
表示領域は質問時90px、それ以外148px。収まる文章は動きません。選択肢とヘッダは固定です。
本文の背景は黒、枠は実行中が緑・入力待ち／エラーが赤・待機／完了がグレーです。
セッション名は枠と同じ緑（`#238a43`）・赤（`#9c263b`）・グレー（`#4d5552`）の帯に黒文字で表示します。
一覧の各セッション名も同じ配色です。フォーカスは太い白枠で示し、切断時はグレーにします。
外枠は液晶端から2px内側の4px幅で、入力待ちは`#9c263b`です。
実機のベゼルで隠れにくい独立したLVGL枠を、シミュレータでも同じ座標に描きます。

| 場面           | C短押し                                  | A短押し                  | B短押し              |
| -------------- | ---------------------------------------- | ------------------------ | -------------------- |
| 本文・回答     | 選択肢を順にフォーカス（末尾から先頭へ） | 選択中の回答を送信       | セッション一覧を開く |
| セッション一覧 | 次のセッションへ（末尾から先頭へ）       | セッションを選択して戻る | 切り替えずに戻る     |

YES／NOではNOを初期選択。その他は先頭の候補を選択します。Aは押して離した時に決定します。
受領確認前に切断した場合は送信待ちを解除し、PCでの確認を促します。再接続だけで回答を再送しません。
一覧には4件ずつ表示し、Cで移動すると表示範囲も追従します。
最大16セッション、各8選択肢。選択肢は2件ずつ表示します。
Cは物理電源スイッチを兼ねるため、1秒以上のC入力を選択移動には使いません。電源操作自体はboard側の責務です。

本文のスクロールと選択位置はセッションごとに保持します。
一覧・ボタン押下中・切断・電源OFFではスクロールを止めます。
同一stateの再受信では位置を保持し、質問・本文・選択肢が変われば先頭へ戻します。
質問変更では進行中の回答操作を無効化します。一覧を開くBと、一覧内のC／Aは、
本文や状態が更新されても操作を継続します。セッション消失・一覧並べ替え、cancel、切断では押下を無効化します。
送信後は重複送信をロックし、対応する受信確認のみ受理します。

## セッションの自動選択

通常は **入力待ち ＞ エラー ＞ 実行中 ＞ 待機／完了** の優先度で表示します。
待機画面を表示中に別セッションが実行を始めた場合も、自動で実行中の画面へ移ります。
同じ優先度では現在の表示を維持し、本文の更新や一覧の並べ替えだけで画面を往復しません。
現在の質問への回答後は、まだ回答していない質問を受信した順に選びます。

- ボタンが押されている間と、Bで開いた一覧の操作中は自動切替を止めます。
- Cで回答を選び始めた場合や、一覧から質問を手動選択した場合は、その質問を固定します。
  回答するか、元の質問が取り下げ・変更されると、自動選択へ戻ります。
- 一覧から選んだ状態画面は10秒間保持して読みやすくします。Bで一覧を閉じた場合は再選択します。
- 回答の受信確認は2秒間表示してから再選択します。この間に同じチャットへ次の質問が届いても、
  Aの追加操作で誤回答しません。受信エラーの場合は質問を固定して、明示的な再操作を待ちます。
- 表示中の実行が待機／完了に変わった場合は2秒間表示してから再選択します。
  入力待ちやエラーはこの完了表示より優先し、再実行が来た場合も表示を更新します。
- 切替前から押されていたボタンを離しても、切替先の質問へ回答しません。

自動選択は表示だけを変え、`uiAction`を生成しません。接続と電源が有効な間だけ動作します。
`snapshot`の`autoPaused`に一時停止の理由、`selectedPriority`に選択中の状態の優先度を出力します。

## メッセージ

単一セッションの更新は既存`state`形式です。`session.id`は必須で、同じIDの状態を更新します。

```json
{
  "type": "state",
  "session": { "id": "s1", "name": "画面の改善" },
  "ui": {
    "id": "q1",
    "state": "waiting",
    "message": "続けますか？",
    "actions": [
      { "id": "yes", "label": "YES", "button": "A" },
      { "id": "no", "label": "NO", "button": "B" }
    ]
  }
}
```

`sessions`は全件のスナップショットです。各要素は上記stateの内容で、含まれないセッションは除去します。
全要素を検証してからまとめて反映し、IDで選択とフォーカスを維持します。
選択対象が消えた場合は残った状態の優先度で再選択し、一覧の操作中なら一覧の表示を維持します。

```json
{
  "type": "sessions",
  "sessions": [
    {
      "session": { "id": "s1", "name": "調査" },
      "agent": { "status": "running", "message": "調査中です" }
    }
  ]
}
```

出力は`uiAction`。`button`は選択肢に付随する既存プロトコル情報で、今回押した物理ボタン（常にA）とは別です。
PC側ではセッションID・質問ID・回答IDを照合して対象へ配送します。

```json
{ "type": "uiAction", "sessionId": "s1", "uiId": "q1", "actionId": "yes", "button": "A" }
```

受信確認には3つのIDと真偽値の`ok`が必要です。別セッションを表示中でも対象の状態だけを更新します。
`ok:false`では選び直し・再送が可能です。`ok:true`では次の質問まで重複送信しません。

```json
{ "type": "ack", "sessionId": "s1", "uiId": "q1", "actionId": "yes", "ok": true }
```

1パケットは64KiBまで、本文は8KiBまで、表示用の高さは30,000pxまでです。
上限超過、セッションや選択肢のID重複、不完全なスナップショットは拒否します。
USB／SPP transport・PCの実セッション収集はProduct側の別実装です。BLEは未実装です。
